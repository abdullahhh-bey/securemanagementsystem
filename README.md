# ExamFlow

## Local development

1. Install Node.js 20.19 or newer and npm.
2. Copy `backend/.env.example` to `backend/.env` and set `DATABASE_URL`, `DIRECT_URL`, and `JWT_SECRET`.
3. Run `npm ci` from the repository root.
4. Apply migrations with `npm run db:migrate --workspace backend`.
5. Start the frontend and backend in separate terminals with `npm run dev:frontend` and `npm run dev:backend`.

## Deploy to Render

This repository includes a Render Blueprint in `render.yaml`. It creates a Node web service and a PostgreSQL database. The web service serves both the frontend and API from one origin, and applies pending Prisma migrations at startup.

1. Push the repository to GitHub.
2. In Render, choose **New → Blueprint**, connect the repository, and apply the `render.yaml` configuration. Render will build and deploy the app. The Blueprint uses free plans; the web service may spin down when idle, and the free database is intended for evaluation rather than production.
3. In the web service's **Environment** settings, add `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, and `SEED_ADMIN_NAME`. Use a unique email and a strong password.
4. Open the service's Shell and run `npm run db:seed --workspace backend` once to create the initial administrator. If Shell is unavailable on your plan, run the same command locally after setting `DATABASE_URL` and `DIRECT_URL` to the database's external connection string and setting the three `SEED_ADMIN_*` values.
5. Visit the service's `onrender.com` URL and sign in with the administrator credentials.

`JWT_SECRET` is generated by Render. `DATABASE_URL` and `DIRECT_URL` are both connected to the Render database. Do not set `VITE_API_URL`: the frontend uses same-origin API requests. For production use, select an appropriate paid Render plan and database tier in the Blueprint or service settings.
